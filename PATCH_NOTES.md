## 0. Присланные `.exe.txt` проверены: файлы целые

Три файла из заливки (`TheEscapists_eur/rus/pol.exe.txt`) — это **правильно
пропатченные exe**, а не испорченные. Совпадение байт-в-байт по содержимому:

| exe | оригинал, байт | sha1 оригинала | с модом, у тебя, байт | sha1 у тебя | мой эталон, байт | sha1 моего эталона |
|---|---|---|---|---|---|---|
| `TheEscapists_eur.exe` | 8000808 | `cf7b416ca19572edee37f3eb30f18d54e39fc279` | 8000927 | `9f2c6105e0034edd07aeff22defb710108b87e86` | 8000920 | `86f9d274e2aa9786c318cc08fc70de4fe2b2d2d5` |
| `TheEscapists_rus.exe` | 8000833 | `d8e5dec339ec546977f69471402e7c169516c128` | 8000952 | `c32351fc6d0e4e5040f2ffd30980d6532af05d57` | 8000945 | `5719956d044e07215cbaeec40d7c9a82fe966bab` |
| `TheEscapists_pol.exe` | 8000824 | `fd8f022aba53f7c84256575a60cb5cfca7eee36c` | 8000943 | `c431867be5e0dbeefe8ce5ad63b6227caeb69236` | 8000936 | `70581800f8e8bd86712d187e93e9e3aae0d9dcd4` |

Что показала проверка (разбор обеих копий на уровне чанков Fusion и событий
фрейма `npc_rename`):

* **События мода совпадают байт-в-байт**: sha1 восстановленного списка событий
  `232e78481d3366ea9cf97a5f29a4deaa3bd216c2` и у тебя, и у меня; пять
  действий `GuardName_1..5` = Cell/Utility/Entrance/Staff/Work Key на месте,
  все остальные 12 фреймов и все группы не тронуты.
* **Разница только в сжатии**: твой Python упаковал тот же самый текст в
  zlib-поток на 7 байт длиннее (eur 5974 против 5967 байт на сабчанк
  `13117`). После распаковки файлы идентичны, поэтому 8000927 и 8000920 —
  **один и тот же мод**, просто собранный другим zlib. Никаких «лишних» или
  потерянных данных в твоих файлах нет: патч добавляет 112 байт, а +119 — это
  112 + 7 из-за компрессии.
* Значит **патч и есть причина «не запускается»** — так выглядеть не может
  только файл, у которого сломаны PE-заголовки или обрезан хвост. Поэтому
  искать надо не в exe, а рядом: антивирус/Windows Security, папка в
  OneDrive, права на папку, «половинчатая» копия игры.

Проверить это на своей машине теперь можно одной командой (см. `--check-exe`
ниже) — она работает и на самом exe, и на `.exe.txt`-копии, которую ты
присылал.

## 0.1 Если игра всё равно не открывается — что запускать

**Ничего вводить в консоль не нужно**: те же проверки теперь в меню лаунчера
(пункт **3. Diagnostics**), а всё, что лаунчер печатает, он одновременно
пишет в файл **`mods\launcher_log.txt`** — его и присылай.

```
   3. Diagnostics
      1. Check every file the game loads   (exe + Data\*.dat)
      2. Show the state of the game executables
      3. Check one file (an exe or a renamed .exe.txt copy)
      4. Put the original files back (all mods off)
      5. Back
```

Ключи командной строки для полноты (то же самое, из cmd в папке игры):

```
TE1_Mod_Launcher.bat --status      состояние мода + размер и sha1 каждого exe и его
                                   чистого бэкапа
TE1_Mod_Launcher.bat --verify      читает все Data\*.dat и exec так, как это
                                   делает игра, и перечисляет всё повреждённое
TE1_Mod_Launcher.bat --check-exe FILE...   проверяет КОНКРЕТНЫЕ файлы (exe или
                                   .exe.txt-копии): VALID / оригинал / DAMAGED
TE1_Mod_Launcher.bat --revert-exe  вернуть оригинальные exe и выключить Guard Key Names
TE1_Mod_Launcher.bat --restore     вернуть оригинальные Data\*.dat
```

### Что показал разбор последнего запуска

* мод встал правильно: `8000808 -> 8000927`, `8000824 -> 8000943`,
  `8000833 -> 8000952` (у тебя zlib даёт на 7 байт больше, чем у меня: это
  тот же патч, см. п. 0);
* предстартовая проверка: все exe `VALID`, все `Data\*.dat` читаются,
  `val.dat` совпадает — **набор файлов здоров**;
* но во время запуска лаунчер увидел игровой процесс, который прожил
  ~2 секунды, и игра закрылась. Это уже другой симптом, чем «файл битый»:
  какой-то exe стартует и падает.

Поэтому в этой сборке (движок 1.3):

* лаунчер печатает и пишет в лог **имена** процессов, которые увидел
  (`TheEscapists.exe`, `TheEscapists_rus.exe`, …) и сколько каждый прожил —
  по логу сразу будет видно, падает фронтенд или игровой exe;
* после того как фронтенд закрылся, лаунчер ждёт появления настоящей игры
  полные 8 секунд (раньше в этом случае хватало 2, и медленный переход можно
  было принять за падение);
* всё, что печатается, дублируется в `mods\launcher_log.txt`.

### Главная проверка: «мод или не мод»

```
3. Diagnostics -> 4. Put the original files back (all mods off)
```

потом запусти игру **не из лаунчера**, а из Steam (или ярлыком):

* игра запустилась → виноват мод, пиши мне (в логе как раз будет видно,
  какой процесс падал, пока мод стоял);
* игра всё равно не запускается → дело не в моде: Windows Security →
  Protection history, папка в OneDrive, неполная копия игры, «Проверить
  целостность файлов» в Steam.

Пример `--check-exe` на твоей заливке:

```
  TheEscapists_eur.exe.txt
    size : 8000927 bytes
    sha1 : 9f2c6105e0034edd07aeff22defb710108b87e86
    known: a patched TheEscapists_eur.exe we have already checked (this is the mod)
           (the patch only adds the events, 112 bytes; a longer file is normal)
    officers renamed: Cell Key, Utility Key, Entrance Key, Staff Key, Work Key
    verdict: VALID - the Guard Key patch is inside and the whole file parses cleanly
```

Что теперь лаунчер делает **сам**, без команд:

1. Перед запуском игры делает **предстартовую проверку** (`--verify`): читает
   все `Data\*.dat` (декодирование + обратная перекодировка + сверка
   `val.dat` с фактическими размерами) и все exe. Если что-то повреждено —
   **игра не запускается вообще**, оригиналы возвращаются, а в логе видно,
   какой файл плохой. Это тот самый случай «мигнуло окно и пропало».
2. Если игра **не появилась** или **закрылась меньше чем за 5 секунд**, пишет
   это прямым текстом и печатает короткий список проверок (`--status`,
   `--verify`, Windows Security → Protection history, OneDrive/копия игры,
   отключение модов по одному, `--revert-exe`).
3. Повреждённый exe по-прежнему лечится сам из `mods\original\exe`, а
   «после записи файл не выжил» — откатывается назад (было в прошлой версии).

Что стоит проверить руками, если `--verify` и `--check-exe` говорят «всё
целое»:

* **Windows Security → Protection history** (и сторонний антивирус): не
  заблокирован ли `TheEscapists*.exe` — после патча файл новый, и «умный»
  антивирус иногда молча не даёт ему стартовать;
* **чем именно запускаешь**: `TheEscapists.exe` (2.4 МБ) — это фронтенд со
  кнопкой Play; игру запускает он, а патчатся 8-мегабайтные
  `TheEscapists_rus/eur/pol.exe`;
* **папка игры**: если она в `Program Files` — нужен запуск .bat от
  администратора (лаунчер сам предлагает UAC); если в OneDrive — файлы могут
  подменяться синхронизацией;
* **целостность**: Steam → «Проверить целостность файлов игры», потом снова
  `TE1_Mod_Launcher.bat --apply` (мод переустановится);
* и пришли мне: `--status`, строку про «закрылась через N секунд» и что
  именно видно при запуске (ничего / мигает окно / ошибка — какая).

### Эталон для сравнения (твой же архив part1/part2, `exe/game/*.exe.txt`)

`certutil -hashfile TheEscapists_eur.exe SHA1` в папке игры должен дать
`86f9d274e2aa9786c318cc08fc70de4fe2b2d2d5` (или `9f2c6105…` — сборка другим

## 1. Рандомизатор: перетасовка имён + прочность (`Decay`)

| Что | Как теперь |
|---|---|
| **Названия предметов** (`Name`) | **перетасовываются между предметами**: «Ключ от камеры» может стать «Чашка в виде оленя». Пул имён не меняется — ни одно название не теряется, ни один предмет не остаётся со своим прежним названием. Один seed → одинаковое соответствие во всех языковых файлах. |
| **Прочность** (`Decay`) | пересчитывается **у каждого предмета**. `Decay` — процент, который предмет тратит за одно использование: `5` = 20 использований, `0` = не изнашивается. Пул: `0, 1, 2, 2, 3, 5, 5, 8, 10, 10, 15, 20, 25`. |
| **Статы** | как раньше: `Weapon`, `Digging`, `Chipping`, `Cutting`, `Unscrewing`, `HP`, `FAT`, `Gift`, `Buy` + `Illegal` на «хаосе». |
| **Не трогается** | `Craft` (крафт в игре идёт по ID предметов), `Info`, `Found`, `Desk`, `Outfit`, `Carry` и прочие поля редактора тюрем. |
| `val.dat` | пересобирается автоматически под новые размеры файлов. |

## 2. Что нового для Guard Key Names (страховки)

1. **Запись exe проверяется чтением обратно**: если файл не выжил на диске
   (антивирус, квота, блокировка) — оригинал возвращается из бэкапа, в логе
   `read-back check failed … the original exe was put back`.
2. **Повреждённый exe лечится сам**: при следующем запуске лаунчер видит
   нечитаемый файл, кладёт на его место чистый из `mods\original\exe` и
   **заново ставит мод** («was damaged — the pristine backup was put back»).
3. **Отказ патчить при запущенной игре** (`the game is still running — close
   it and try again`), вместо непонятной ошибки блокировки Windows.
4. **`--status` печатает размер и sha1** каждого exe и бэкапа, плюс строку
   `check:` с вердиктом (`VALID` / `OK, the mod is NOT installed` /
   `DAMAGED`); сам `.bat` пробрасывает ключи командной строки в движок.
5. **`--check-exe`, `--verify`, `--revert-exe`** — проверка конкретных файлов,
   предстартовая проверка всей папки и откат exe одним ключом (см. п. 0.1).
6. **Проверка перед запуском**: если хоть один файл повреждён — игра не
   запускается на сломанном наборе, оригиналы возвращаются, а в консоли
   написано, что именно плохо.
7. **Самолечение «игра не появилась»**: если игра вообще не стартовала, лаунчер
   не только вернёт Data-файлы, но и **снимет патч с exe** и выключит мод —
   следующий запуск пойдёт на оригинальном exe, без ручных действий. Включить
   мод обратно можно в Mod Workshop.

Что проверено на реальных exe: патченый файл разбирается целиком (все 12
фреймов, каждая группа до последнего байта: `npc_rename` 55832/55832,
`game` 2420852/2420852, `tutorial` 760062/760062), движок и одиночный патчер
дают байт-в-байт одинаковый файл, в exe нет ссылок на собственный размер и
нет Authenticode-подписи, движения только в кадре `npc_rename` (все остальные
чанки — байт-в-байт), e2e-тесты — ALL GOOD (установка, идемпотентность,
лечение после Steam «проверить целостность», откат, откат при порче записи,
лечение повреждённого файла, `--check-exe` на exe/`.txt`/битом файле/папке,
`--verify` на битых Data-файлах, `--revert-exe`).
